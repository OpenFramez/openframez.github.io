## فاز ۰: آماده‌سازی قبل از انتشار (Phase 0 — Pre-Launch)

**هدف:** رفع مسائل امنیتی بحرانی و تثبیت زیرساخت قبل از هرگونه دعوت از کاربران.

**مدت زمان تخمینی:** ۱–۲ روز کاری

### تسک‌ها

#### 0.1Deploy Cloudflare Worker برای OAuth CORS proxy
- **چرا:** `proxy.cors.sh` یک سرویس عمومی رایگان است که rate limit دارد و ممکن است قطع شود. این پایداری ورود کاربران را تهدید می‌کند.
- **چگونه:**
  1. وارد داشبورد Cloudflare شوید
  2. Wrangler CLI را نصب کنید: `npm install -g wrangler`
  3. به پوشه `/cloudflare-worker` بروید
  4. `wrangler login` و سپس `wrangler deploy`
  5. URL Worker را بگیرید (مثلاً `https://pixelary-oauth.{your-subdomain}.workers.dev`)
  6. در `assets/js/oauth.js` مقدار `OAUTH_PROXY_BASE` را به URL Worker جدید تغییر دهید
  7. تست: لاگین را روی production امتحان کنید
- **معیار خروج:** Worker deployed و OAuth روی production از طریق آن کار می‌کند.

#### 0.2 چرخش bot PAT
- **چرا:** PAT فعلی (`ghp_<REDACTED>`) در تاریخچه Git قابل مشاهده است. هر کسی می‌تواند آن را پیدا کرده و به repocentral دسترسی پیدا کند.
- **چگونه:**
  1. در GitHub: Settings → Developer settings → Personal access tokens
  2. PAT قدیمی را `Revoke` کنید
  3. PAT جدید با scope `public_repo` بسازید
  4. PAT جدید را در `assets/js/repo.js` جایگزین کنید (یا به‌ترتیب در GitHub Secret ذخیره کنید و از طریق build step تزریق کنید)
  5. **بهتر:** استفاده از GitHub Actions برای inject کردن PAT در زمان build تا در سورس کد visible نباشد
- **معیار خروج:** PAT قدیمی revoked شده و PAT جدید کار می‌کند.

#### 0.3 تأیید نهایی رفع باگ انتخاب فایل
- **چرا:** fix اعمال شد ولی روی همه مرورگرها تست نشده است.
- **چگونه:**
  1. روی Chrome Android، Safari iOS، Firefox Android تست کنید
  2. هر سه دکمه (گالری، دوربین، ضبط ویدیو) را امتحان کنید
  3. روی desktop با drag-and-drop و کلیک تست کنید
  4. نتیجه را در GitHub Issue با label `qa` ثبت کنید
- **معیار خروج:** حداقل ۳ دستگاه موبایل + ۲ desktop بدون مشکل فایل انتخاب می‌کنند.

#### 0.4 بررسی نهایی فرآیند آپلود end-to-end
- **چرا:** مطمئن شویم تمام pipeline (login → upload → manifest → license → NOTICE → registry → federation) کار می‌کند.
- **چگونه:**
  1. با یک اکانت GitHub تست جدید لاگین کنید
  2. یک عکس آپلود کنید
  3. بررسی کنید که در مخزن `pixelary-uploads` کاربر: فایل عکس، `*.LICENSE.txt`، `manifest.json`، `NOTICE.md`، `LICENSE` (CC0) همه به‌درستی ایجاد شده‌اند
  4. بررسی کنید که `data/registry.json` در repo central به‌روز شده است
  5. صبر کنید تا federation اجرا شود (حداکثر ۱ ساعت) و بررسی کنید که فایل در `data/federated.json` ظاهر می‌شود
  6. در گالری اصلی پیکسلری، محتوای جدید را ببینید
- **معیار خروج:** کل pipeline بدون خطا کار می‌کند و محتوا در گالری central ظاهر می‌شود.

#### 0.5 تست سیستم گزارش خطا
- **چرا:** مطمئن شویم خطاها واقعاً به GitHub Issues می‌روند.
- **چگونه:**
  1. یک خطای عمدی در console ایجاد کنید (مثلاً `throw new Error('test')`)
  2. دکمه feedback را بزنید و یک گزارش ارسال کنید
  3. در GitHub Issues بررسی کنید که issue با label `user-report` ایجاد شده است
- **معیار خروج:** هر دو نوع گزارش (auto و manual) در GitHub Issues ظاهر می‌شوند.

### معیار ورود به فاز ۱
- ✅ Cloudflare Worker deployed و OAuth روی آن کار می‌کند
- ✅ PAT قدیمی revoked شده
- ✅ انتخاب فایل روی حداقل ۵ دستگاه/مرورگر تست شده
- ✅ Pipeline آپلود end-to-end تأیید شده
- ✅ سیستم گزارش خطا کار می‌کند

## فاز ۱: انتشار اولیه (Soft Launch)

**هدف:** دعوت از یک گروه کوچک کاربران (۱۰–۵۰ نفر) برای تست واقعی و کشف باگ‌های پنهان.

**مدت زمان تخمینی:** ۱–۲ هفته

### تسک‌ها

#### 1.1 دعوت از کاربران تست (beta testers)
- از طریق کانال‌های شخصی، توییتر، یا انجمن‌های مرتبط
- هدف: ۱۰–۵۰ کاربر فعال
- معیار: حداقل ۱۰ کاربر حداقل ۱ آپلود موفق داشته باشند

#### 1.2 مانیتورینگ خطاها
- روزانه GitHub Issues با label `user-report` را بررسی کنید
- خطاهای تکراری را first-class issues تبدیل کنید
- پاسخ سریع (زیر ۲۴ ساعت) به کاربرانی که گزارش داده‌اند

#### 1.3 مانیتورینگ federation
- هر روز `data/federated.json` را بررسی کنید
- مطمئن شوید همه کاربران ثبت‌شده در `registry.json` به‌درستی fetch می‌شوند
- اگر کاربری repo خود را حذف کرده، او را از registry پاک کنید

#### 1.4 بهبود UX بر اساس بازخورد
- احتمالاً کاربران گیج می‌شوند که چرا باید GitHub account داشته باشند
- راهنمایی بهتر برای کاربران غیرفنی
- شاید اضافه کردن ویدیوی آموزشی کوتاه

#### 1.5 مستندسازی کاربر
- صفحه `help.html` یا بخش در `about.html` با:
  - چگونه اکانت GitHub بسازیم
  - چرا محتوا روی حساب خود من است
  - چگونه محتوا را حذف کنم
  - لایسنس‌ها چیست و کدام را انتخاب کنم

### معیار ورود به فاز ۲
- ✅ حداقل ۱۰ کاربر فعال
- ✅ حداقل ۲۰ آپلود موفق
- ✅ نرخ خطای آپلود زیر ۵٪
- ✅ بازخورد مثبت از حداقل ۵ کاربر
- ✅ باگ‌های بحرانی گزارش‌شده رفع شده‌اند

## فاز ۲: بهینه‌سازی و رفع باگ (Optimization)

**هدف:** رفع مشکلات کشف‌شده در soft launch و بهبود تجربه کاربری.

**مدت زمان تخمینی:** ۲–۳ هفته

### تسک‌ها

#### 2.1 اضافه کردن صفحه پروفایل کاربر
- مسیر: `profile.html?user={username}`
- نمایش تمام محتوای آپلودشده توسط یک کاربر
- لینک از روی هر آیتم گالری به پروفایل کاربر
- اضافه کردن به sitemap و service worker cache

#### 2.2 اضافه کردن قابلیت حذف محتوا
- در صفحه آپلود موفق، دکمه "حذف این محتوا" اضافه کنید
- حذف از طریق GitHub API (محتوای کاربر، فایل LICENSE، ورودی manifest)
- بعد از حذف، فدراسیون در اجرای بعدی به‌روز می‌شود
- **نکته امنیتی:** فقط کاربری که محتوا را آپلود کرده می‌تواند حذف کند (token او فقط دسترسی به repo خودش دارد)

#### 2.3 بهبود شاخص‌گذاری federation
- اضافه کردن `etag` یا `last-modified` به `manifest.json` تا aggregator بتواند فقط تغییرات را fetch کند
- بررسی `If-None-Match` header در `aggregate_federation.py`
- این کار rate limit مصرفی GitHub را کاهش می‌دهد

#### 2.4 اعتبارسنجی محتوا (Moderation) — حداقل نسخه
- اضافه کردن دکمه "گزارش محتوای نامناسب" روی هر آیتم
- گزارش به GitHub Issues با label `moderation`
- تیم به‌صورت دستی بررسی و در صورت لزوم از registry حذف می‌کند
- **نسخه آینده:** استفاده از GitHub Actions با Computer Vision API برای تشخیص خودکار

#### 2.5 بهبود SEO
- اضافه کردن `schema.org/ImageObject` و `schema.org/VideoObject` با فیلد `license`
- اضافه کردن `isAccessibleForFree: true`
- اضافه کردن `copyrightHolder` و `creator` در JSON-LD
- تولید sitemap داینامیک از `federated.json`

#### 2.6 اضافه کردن ETag/Cache headers بهینه
- فعلاً `federated.json` بدون cache header مناسب serve می‌شود
- استفاده از `Cache-Control: max-age=3600` برای `federated.json` (یک ساعت)
- استفاده از `stale-while-revalidate` در service worker

#### 2.7 فیلتر محتوا بر اساس لایسنس
- در گالری، فیلتر "فقط محتوای CC0" یا "فقط محتوای قابل استفاده تجاری" اضافه کنید
- مفید برای کاربرانی که می‌خواهند محتوا را reuse کنند

#### 2.8 صفحه آمار
- تعداد کل کاربران، عکس‌ها، ویدیوها
- پرترین دسته‌بندی‌ها
- جدیدترین کاربران
- نمایش در `about.html` یا صفحه اختصاصی `stats.html`

### معیار ورود به فاز ۳
- ✅ صفحه پروفایل کاربر فعال
- ✅ حذف محتوا از UI کار می‌کند
- ✅ نرخ خطای آپلود زیر ۱٪
- ✅ moderation workflow تعریف‌شده
- ✅ SEO audit score بالای ۹۰ (در Lighthouse)

## فاز ۳: رشد و مقیاس‌پذیری (Growth & Scale)

**هدف:** پذیرش حجم بالاتر کاربران و محتوا، و انتشار عمومی.

**مدت زمان تخمینی:** ۱–۲ ماه

### تسک‌ها

#### 3.1 انتشار عمومی (Public Launch)
- آماده‌سازی announcement blog post
- انتشار در Hacker News، Reddit، توییتر، انجمن‌های فارسی
- همراه با یک ویدیوی معرفی کوتاه

#### 3.2 بهبود عملکرد گالری
- pagination یا virtual scrolling برای گالری (وقتی تعداد آیتم‌ها بیش از ۲۰۰ شد)
- lazy-load thumbnail‌ها با `IntersectionObserver`
- prefetch تصاویر بندانگشتی صفحه بعد

#### 3.3 جستجوی full-text
- فعلاً جستجو فقط روی عنوان و توضیحات است
- اضافه کردن جستجوی fuzzy (با libraries مثل Fuse.js)
- index کردن توسط aggregator و serve از `data/search_index.json`

#### 3.4 صفحات موضوعی
- `/category/nature.html` برای هر دسته‌بندی
- محتوای اسکرپ‌شده + محتوای کاربران در یک صفحه
- بهتر برای SEO و discoverability

#### 3.5 RSS Feed
- `feed.xml` از جدیدترین آپلودها
- مشترکین می‌توانند جدیدترین محتوا را دنبال کنند
- مفید برای AI indexers و aggregator‌های دیگر

#### 3.6 API عمومی
- `data/federated.json` فعلاً serve می‌شود ولی مستند نیست
- اضافه کردن صفحه `api.html` با مستندات
- اضافه کردن rate limit (با Cloudflare Worker)
- حمایت از third-party apps که روی پیکسلری ساخته می‌شوند

#### 3.7 بهبود PWA
- Push notifications برای محتوای جدید (نیازمند server)
- Background sync برای آپلودهای قطع‌شده
- بهبود offline mode با cache‌های هوشمندتر

#### 3.8 مانیتورینگ و آنالیتیکس
- اضافه کردن Plausible یا Umami (privacy-friendly analytics)
- صفحات پر بازدید، نرخ conversion آپلود، نرخ خطا
- A/B testing برای صفحات کلیدی

## فاز ۴: قابلیت‌های پیشرفته (Advanced Features)

**هدف:** تمایز از رقبا و اضافه کردن قابلیت‌های power-user.

**مدت زمان تخمینی:** مستمر

### تسک‌ها

#### 4.1 سیستم Collections
- کاربران می‌توانند collections از محتوای خود و دیگران بسازند
- اشتراک‌گذاری collections با URL
- "Best of nature"، "My favorites" و...

#### 4.2 سیستم following کاربران
- کاربران می‌توانند دیگران را دنبال کنند
- صفحه feed با جدیدترین محتوای کاربران دنبال‌شده
- نیازمند storage برای graph (می‌تواند با GitHub gist یا user repo)

#### 4.3 آپلود چندفایلی
- انتخاب چند فایل همزمان
- تکمیل متادیتا به‌صورت bulk
- مفید برای کاربرانی که می‌خواهند آلبوم عکس آپلود کنند

#### 4.4 ویرایش متادیتا
- کاربر می‌تواند عنوان، توضیحات، دسته‌بندی را بعد از آپلود ویرایش کند
- نهفته در manifest.json کاربر

#### 4.5 نسخه‌بندی محتوا
- اگر کاربر فایل را با نسخه جدید جایگزین کرد، نسخه قدیمی حفظ شود
- با git history مخزن کاربر به‌طور طبیعی پشتیبانی می‌شود

#### 4.6 پشتیبانی از محتوای ۳D و VR
- فایل‌های `.glb`، `.gltf`
- نمایش با `<model-viewer>` یا three.js
- پروفایل‌های جدید برای کاربران خالق محتوای ۳D

#### 4.7 پشتیبانی از محتوای صوتی
- فایل‌های `.mp3`، `.ogg`
- پلیر سفارشی با waveform visualization
- پادکست‌ها، موسیقی، افکت‌های صوتی

#### 4.8 سیستم درآمدزایی (اختیاری)
- Tips / Donations برای خالقان محتوا (با GitHub Sponsors)
- Badge تأیید شده برای خالقان فعال
- Nereds بررسی: فقط کاربرانی که حداقل N آپلود دارند می‌توانند tip دریافت کنند

## جمع‌بندی

پلتفرم پیکسلری در حال حاضر در **اواخر فاز ۰** قرار دارد — زیرساخت اصلی کار می‌کند، اما دو مسئله بحرانی امنیتی/پایداری باقی مانده:

1. **Deploy Cloudflare Worker** (سمت پایداری OAuth)
2. **چرخش bot PAT** (سمت امنیت)

پس از رفع این دو مورد، آماده ورود به **فاز ۱ (Soft Launch)** است. پیشنهاد می‌شود قبل از دعوت عمومی، حداقل ۱ هفته تست خصوصی با ۳–۵ کاربر довер‌شده انجام شود تا باگ‌های پنهان کشف شوند.

ویژگی **اعمال خودکار لایسنس** که در این جلسه تکمیل شد، یک متمایزکننده کلیدی است — پلتفرم‌های مشابه معمولاً فقط یک لایسنس سراسری اعمال می‌کنند، در حالی که پیکسلری:
- لایسنس دو‌لایه دارد (CC0 برای متادیتا + لایسنس انتخابی کاربر برای محتوا)
- هر فایل SPDX-ID机器-readable دارد
- NOTICE.md خودکار به‌روزرسانی می‌شود
- زنجیره اعتبار ویروسی (با CC BY-SA) به‌صورت صریح در LICENSE file ذکر می‌شود

این معماری لایسنس، پیکسلری را برای استفاده توسط AI indexers و downstream aggregators آماده می‌کند — یک مزیت رقابتی مهم در عصر AI.
